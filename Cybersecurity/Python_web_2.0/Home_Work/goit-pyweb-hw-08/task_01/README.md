# Retro-Tech Quotes Database

Консольний пошуковий застосунок для цитат, створений на Python з використанням MongoDB Atlas, MongoEngine та Redis caching. Побудований на основі багатошарової архітектури (Repository → Service → Controller) і стилізований під ретро-термінал.

## 📌 Опис проєкту

Retro-Tech Quotes Database — це консольний застосунок для пошуку цитат за:
*іменем автора
*частиною імені автора (через regex / регулярні вирази)
*одним тегом
*частиною тегу
*кількома тегами (через логіку OR)

Проєкт демонструє практичне використання:
*MongoDB Atlas для хмарного зберігання даних.
*MongoEngine (ODM) для об'єктно-орієнтованої роботи з MongoDB.
*Redis для кешування повторних запитів.
*Poetry для керування залежностями.
*Багатошарової архітектури (Layered Architecture) для чіткого розділення відповідальностей.
*ANSI-стилізованого виводу для ефекту ретро-терміналу.

Це сильний навчальний та портфоліо-проєкт, який добре показує базові принципи Python backend-розробки, NoSQL-моделювання, кешування та чистої архітектури.

```text
✨ Основні можливості
*🔍 Пошук цитат за точним ім'ям автора.
*🔎 Пошук цитат за частиною імені автора через MongoDB regex.
*🏷 Пошук за одним тегом.
*🧩 Пошук за частиною тегу.
*🏷🏷 Пошук за кількома тегами (логіка OR).
*⚡ Redis caching для пришвидшення повторних запитів.
*☁️ Підключення до хмарної бази MongoDB Atlas.
*🧱 Архітектура у стилі SOLID.
*🖥 Стилізований Retro-Tech Terminal.
*🧹 Окремий скрипт для очищення БД перед повторним завантаженням.
```

## 🏗 Архітектура проєкту

### Проєкт побудований за принципом багатошарової архітектури

1. Repository Layer → прямі запити до бази даних.
2. Service Layer → бізнес-логіка та кешування.
3. Controller Layer → обробка команд користувача.
4. Config Layer → ініціалізація підключень (MongoDB та Redis).
5. Utility Layer → логування та стилізація виводу.

### Переваги такого підходу

1. Простіше підтримувати код.
2. Легше тестувати окремі частини.
3. Зручніше масштабувати.
4. Простіше перетворити консольний застосунок у REST API (наприклад, за допомогою FastAPI) у майбутньому.

## ⚙️ Встановлення та налаштування

### 1. Клонування репозиторію

```text
git clone [your-repository-url]
cd retro-tech-quotes-db
```

### 2.Встановлення залежностей

Якщо Poetry ще не встановлений:

```text
pip install poetry
```

Встановіть залежності проєкту:

```text
poetry install
```

### 3.Налаштування MongoDB Atlas

1. Перейди на MongoDB Atlas.
2. Створи новий Project та натисни Build a Database.
3. Обери безкоштовний тариф M0 Free.
4. Створи користувача БД (username + password).
5. Додай мережевий доступ (Network Access): 0.0.0.0/0 (тільки для розробки!).
6. Натисни Connect → Обери Drivers → Driver: Python (Version: 3.6 or later).
7. Скопіюй connection string.

Налаштування кластера бази даних — це відмінний практичний крок для занурення у хмарну інженерію.
Використання Python разом з ODM (Object-Document Mapper) Mongoengine дозволяє зручно та структуровано керувати цими даними через об'єктно-орієнтований підхід.

#### Ось детальна покрокова інструкція

##### 1.Створення хмарної бази даних Atlas MongoDB

MongoDB Atlas — це хмарний сервіс, який надає повністю керовану базу даних MongoDB.

##### 2.Реєстрація та створення кластера

1. Перейдіть на сайт MongoDB Atlas і зареєструйтеся (або увійдіть).
2. Створіть нову організацію та проект.
3. Натисніть "Build a Database" (або "Create Cluster").
4. Оберіть безкоштовний тариф "M0 Free" (Sandbox).
5. Виберіть будь-якого хмарного провайдера (наприклад, AWS) та найближчий до вас регіон (наприклад, Frankfurt).
6. Натисніть "Create".

##### 3.Налаштування доступу користувача (Database Access)

1. У лівому меню знайдіть розділ Security -> Database Access.
2. Натисніть "Add New Database User".
3. Виберіть метод автентифікації "Password". Введіть логін (наприклад, admin) та згенеруйте надійний пароль. Обов'язково збережіть цей пароль, він знадобиться для підключення у коді. Натисніть "Add User".

##### 4.Налаштування мережевого доступу (Network Access)

1. У лівому меню перейдіть до Security -> Network Access.
2. Натисніть "Add IP Address".
3. Для розробки найпростіше вибрати "Allow Access from Anywhere" (додасться IP 0.0.0.0/0). Натисніть "Confirm". (У реальних проектах сюди додають лише конкретні IP-адреси серверів задля безпеки).

##### 5.Отримання рядка підключення (URI)

1. Перейдіть у розділ Database (де ваш кластер).
2. Натисніть кнопку "Connect".
3. Оберіть "Drivers" (Connect your application).
4. Виберіть Driver: Python та Version: 3.6 or later.
5. Скопіюйте наданий рядок (Connection String). Він виглядатиме приблизно так:
mongodb+srv://[username]:[password]@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
Цей рядок ви будете використовувати у своєму файлі .env, замінивши [username] та [password] на створені у кроці 2.
Важливо: Замініть [username] на ім'я користувача бази даних, а [password] — на його пароль (без кутових дужок []].
6. Щоб створити конкретну базу, додайте її ім'я перед знаком ?, наприклад: ...mongodb.net/quotes_db?retryWrites...

### 4.Налаштування змінних середовища

У корені проєкту створи файл .env і додай туди свої дані:

```text
MONGODB_URI=mongodb+srv://[username]:[password]@cluster0.a1b2c.mongodb.net/quotes_db?retryWrites=true&w=majority
REDIS_HOST=localhost
REDIS_PORT=6379
```

⚠️ Важливо: Ніколи не додавай файл .env у систему контролю версій (GitHub). Він має бути в .gitignore.

### 5.Запуск Redis через Docker

Запуск Redis у фоновому режимі:

```text
docker run --name redis-cache -p 6379:6379 -d redis
```

Перевірка, що контейнер запущений:

```text
docker ps
```

### 6.Підготовка файлів даних

Переконайтеся, що в кореневій папці знаходяться файли authors.json та quotes.json.

## 🚀 Запуск проєкту

Крок 1: Очистити базу даних (рекомендовано)

Перед першим або повторним завантаженням даних очистіть базу, щоб уникнути дублікатів:

```text

```

Крок 2: Запустити застосунок

```text
poetry run python main.py
```

### Під час запуску застосунок

1. Підключиться до MongoDB Atlas та Redis.
2. Прочитає дані з JSON-файлів та завантажить їх у БД (якщо вони ще не завантажені).
3. Запустить інтерактивний термінал для пошуку.
4. 💻 Використання (Команди терміналу)

### У стилізованому терміналі ви можете вводити такі команди

🔍 Пошук цитат за ім'ям автора

#### 1) Пошук за точним ім'ям автора

```text
name: Albert Einstein
```

Повертає всі цитати Альберта Ейнштейна.

```text
name: Steve Martin
```

Повертає всі цитати Steve Martin.

#### 2)Пошук за частиною імені автора (regex)

```text
name: Al
```

Використовує регулярні вирази MongoDB і знайде, наприклад, "Albert Einstein".

#### 3)Пошук за точним тегом

```text
tag: life
```

#### 4)Пошук за частиною тегу

```text
tag: li
```

Може знайти теги типу: life, live, light.

#### 5)Пошук за кількома тегами (логіка OR)

```text
tags: success,humor
```

Повертає цитати, які відповідають хоча б одному з переданих тегів.
⚠️ Важливо: Не ставте пробіли після коми. Правильно: tags: success,humor.

#### 6)Вихід із програми

```text
exit
```

### ⚡ Як працює кешування в Redis

#### Застосунок кешує результати пошуку

Спробуйте ввести одну й ту саму команду двічі поспіль, наприклад:
Plaintext

```text
name: Steve Martin
```

#### Перший запит

Застосунок перевіряє Redis → кешу немає → виконує запит до MongoDB... (дані беруться з хмари).
У консолі з'явиться лог: [DB] Executing query in MongoDB...

#### Повторний запит

Застосунок перевіряє Redis → кеш є → повертає результат з кешу.
У консолі з'явиться лог: Той самий запит миттєво повертається з Redis.
У консолі з'явиться лог: [SYS] Data retrieved from Redis cache... (дані беруться миттєво з оперативної пам'яті вашого Docker-контейнера).

Чому це важливо? Це типовий backend-патерн оптимізації, що покращує швидкість відповіді, зменшує навантаження на БД та підвищує масштабованість.

2. born_date (String)

## 🛠 Типові проблеми та рішення

### ❌ Проблема: Не вдається підключитися до MongoDB

1. Причина: У .env використовується шаблонна адреса замість реальної.
2. Рішення: Переконайтеся, що ви скопіювали реальний Connection String з MongoDB Atlas і замінили [username] та [password] у .envrd>.

### ❌ Проблема: Не підключається Redis / Connection Error

1. Причина: Docker-контейнер з Redis не запущений.
2. Рішення: Перевірте статус docker ps. Якщо він зупинений, виконайте docker start redis-cache. Якщо його немає — створіть заново (див. розділ "Встановлення").

### ❌ Проблема: З'являються дублікати цитат у пошуку

1. Причина: Дані з JSON були завантажені кілька разів.
2. Рішення: Зупиніть застосунок, виконайте poetry run python clean_db.py, а потім знову запустіть main.py.
