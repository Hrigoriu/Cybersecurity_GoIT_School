## Опис проєкту

Цей проєкт демонструє **асинхронну архітектуру обробки повідомлень** за допомогою **RabbitMQ** та **MongoDB**.

Система працює за таким принципом:

1. `producer.py` створює контакти.
2. Контакти зберігаються в **MongoDB**.
3. Ідентифікатори контактів (`ObjectId`) надсилаються в черги **RabbitMQ**.
4. Окремі consumer-процеси обробляють Email та SMS повідомлення.
5. Після "відправки" статус у базі даних оновлюється.

## Основні можливості

## Налаштування середовища

Створіть файл .env у корені проєкту.

Приклад .env

```text
MONGO_URI=mongodb://localhost:27017/med_notification_system
RABBITMQ_HOST=localhost
RABBITMQ_PORT=5672
```

Примітка: за потреби додайте інші змінні, якщо вони використовуються у вашій реалізації (RABBITMQ_USER, RABBITMQ_PASSWORD, назви черг тощо).

## Запуск інфраструктури

### Як запустити

1.Запуск RabbitMQ

```text
docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management
```

5672 — AMQP порт для застосунку
15672 — Web UI RabbitMQ Management

2.Запуск MongoDB

```text
docker run -d --name mongodb -p 27017:27017 mongo
```

## Запуск застосунку

Для коректної роботи використовуйте 3 окремі термінали.

1.Запуск Email Consumer

```text
poetry run python consumer_email.py
```

Приміта: Ви побачите зелене повідомлення, що Email Consumer запущено.
Розділіть термінал на дві частини.
Для цього натисніть іконку Split Terminal (кнопка у вигляді двох панелей зверху праворуч у вікні терміналу) або натисніть Ctrl + Shift + 5.

2.Запуск SMS Consumer
У новій (правій) половині терміналу запустіть обробник SMS:

```text
poetry run python consumer_sms.py
```

Приміта: Ви побачите зелене повідомлення, що SMS Consumer запущено.

3.Запуск Producer
Тепер, коли обидва "слухачі" працюють, нам потрібно згенерувати дані.
Ще раз розділіть термінал (Ctrl + Shift + 5), щоб у вас було 3 віконця терміналу поруч.
У третьому вікні запустіть генератор:

```text
poetry run python producer.py
```

Приміта: У вікні producer.py побіжать логи про створення контактів та відправку їх ObjectID у черги.
У вікнах consumer_email.py та consumer_sms.py миттєво почнуть з'являтися логи про отримання цих ObjectID, імітацію відправки повідомлень (з невеликою затримкою) та оновлення статусу в базі даних на True.

Щоб зупинити роботу консюмерів, просто клікніть у відповідне вікно терміналу та натисніть Ctrl + C.

## Як це працює

Крок 1 — Producer
producer.py:
*створює контакти;
*зберігає їх у MongoDB;
*надсилає ObjectId контактів у RabbitMQ.

Крок 2 — Consumers
consumer_email.py та consumer_sms.py:
*отримують ObjectId з відповідної черги;
*знаходять запис у MongoDB;
*імітують відправку повідомлення;
*оновлюють статус доставки (True).

Крок 3 — Логування
У консолі відображаються:
*створення контактів;
*надсилання повідомлень у чергу;
*отримання повідомлень consumer-процесами;
*успішне оновлення статусу в MongoDB.

---

## Очікуваний результат

Після запуску producer.py:
*у логах producer з’являться повідомлення про створення контактів;
*ObjectId буде відправлено в RabbitMQ;
*Email та SMS consumers отримають повідомлення;
*статус доставки в MongoDB буде оновлено.
